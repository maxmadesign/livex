# X 光镜（全身版）

站到屏幕前，摄像头画面上叠出你自己的骨架：全身入镜时是整副骨架，走近后头部换成精细的头骨，还可以打开大脑和面部肌肉；
举起手能看到会动的手骨。骨架会按每个人量出来的比例调整，而不是把同一副模型等比放大缩小。画面只在本机处理，不上传。

这是为 LiveX 的竖屏写的版本（32 寸壁挂屏和 86 寸落地屏），代码是重新写的，不包含原版 X-Ray Mirror 的代码。
原版的拆解和性能补丁在 [`../xray-teardown/`](../xray-teardown/)。

```
index.html   页面本身（界面、追踪、绘制，全部在这一个文件里）
data/        人体模型：body.*（全身骨架）和 head.*（头部各层和带关节的手），各有完整版和轻量版两档
tools/       生成数据、打包单文件、离线依赖、自动化测试的脚本
```

## 打开方式

- **放到任意静态网站**（含 GitHub Pages），访问 `…/xray/`。
- **单个文件**：`python3 tools/bundle.py` 生成 `dist/xray-mirror.html`（5.5 MB，模型数据已内嵌），拷到屏幕上双击即可。
- 浏览器用 Chrome 或 Edge。第一次启动要联网下载运行库和追踪模型，共约 28 MB（three.js 1.3 MB、MediaPipe 运行库 9.8 MB、
  身体/脸/手三个模型 17.4 MB），之后走浏览器缓存。没有网络的屏幕见下面的“离线”。
- 摄像头权限要求页面来自 `https://` 或 `localhost`。直接双击打开的本地文件也能用，但浏览器每次都会再问一遍。

## 一位访客经历的流程

1. **待机**：6 秒没有人时，屏幕中间出现邀请卡片（“站到屏幕前，看看自己的骨架”），镜像画面照常显示。
2. **有人出现**：一条光带从头到脚扫过，扫过的地方露出骨骼；体型参数在这一秒内量好。
3. **引导**：一次只出一句提示，每位访客每句只出一次，中间留有间隔——先是“走近一点，看看头骨和大脑”，走近后是“张开嘴试试”，
   然后是“举起手，看看手骨”和“点按钮切换图层”。访客自己打开了某个图层时，与那个图层有关的提示优先。
4. **短暂丢失**：追踪器偶尔漏掉一帧时，骨架保持上一个姿势并淡出，不会一闪一闪。
5. **离开**：骨架淡出；25 秒后图层恢复成只显示骨骼，等下一位。下一位出现时体型参数重新量。

启动也是流程的一部分：页面一打开就并行下载模型数据、运行库和身体追踪器；摄像头就绪后先显示身体骨架，
脸和手的追踪器在后台接着加载。第一次在竖屏上打开时，开始卡片上可以直接点选这是 32 寸还是 86 寸屏。

## 两块竖屏

| 屏幕 | 怎么进入 | 界面怎么排 |
|---|---|---|
| 32 寸竖屏 | 竖屏默认就是它 | 用满整屏：状态条在顶部，图层按钮在底部 |
| 86 寸竖屏 | 在开始卡片上点“86 寸竖屏”，或地址加 `?screen=86`，或在设置里选 | 状态、图层按钮、提示、开始卡片、待机卡片和设置面板都收在屏幕中间偏上的一条带里：中线在屏幕高度的 58%（从底边量），上下共占 50% 的屏高（也就是屏高的 33%–83%）。状态在左，图层按钮竖排在右，卡片和提示居中。按钮和文字相对屏幕缩到 62%，实物尺寸约为 32 寸屏上的 1.5 倍 |
| 横屏、电脑 | 横屏默认 | 按钮在底部居中 |

- 两种竖屏下，镜像画面和骨架都铺满整屏，收拢的只是界面。
- 中线可以调：设置里的“界面中线高度”（35%–75%），或地址加 `?base=60`。
- 浏览器分不出 32 寸和 86 寸（它只知道像素数），所以 86 寸要指定一次。选过的设置记在这台设备上，下次不用再选。

## 体型适配

同一副骨架只按大小套到每个人身上会显得不对：小孩的头相对身体大得多，有人肩宽有人髋宽，有人壮有人瘦。
页面把追踪器能量到的东西归结成几个数，每个数都在约一秒的时间尺度上平滑，再用它们改模型的形状：

| 量什么 | 怎么量 | 改什么 |
|---|---|---|
| 各段的长度和宽度 | 追踪到的关节之间的距离 | 每根长骨按自己的长度缩放；胸廓的宽度跟肩宽、高度跟躯干长；骨盆的宽度跟髋宽。高矮和四肢比例由此而来 |
| 头的大小 | 眼线到嘴线的距离、两耳的距离 | 远景的头骨按量到的头的大小画，不再按身体大小推算 |
| 头身比（`child`，0–1） | 头的大小 ÷ 身体的大小，比成人大出多少 | 脑颅相对面部放大（最多 26%），长骨变细，胸廓变圆 |
| 肩宽 ÷ 躯干长（`frame`，−1–1） | 仅在躯干完整入镜且正对镜头时 | 长骨粗细 ±7% |
| 髋宽 ÷ 肩宽（`hips`，−1–1） | 同上 | 髋宽的人：髂骨翼外展、骨盆略矮；髋窄的人相反 |
| 胖瘦（`build`，−1–1） | 身体轮廓里上臂、大腿、腰的宽度 ÷ 骨骼长度；仅在有身体轮廓时 | 长骨粗细 ±6%，下部肋骨略张开，胸廓略深 |

- **不做年龄和性别识别。** 男女骨架的可见差别主要是比例（肩宽、骨盆宽、骨骼粗细、身高），这些直接从每个人身上量，
  而不是先把人归到“男”或“女”再换模型。头身比大只意味着“这个头相对身体偏大”，不是判断“这是儿童”。
- **身体轮廓**（设置里的“身体轮廓”）：有显卡加速时，身体追踪器同时给出人的轮廓，压暗的区域就是访客本人的形状，
  不论体型和衣着。没有显卡时这个选项会让追踪器崩溃（tasks-vision 0.10.14），所以那时不启用，压暗区域改按关节勾画，胖瘦这一项保持中性。
- 变化的幅度是有意压小的：量出来的比例带有噪声，衣服也会算进轮廓里。
- 设置里的“体型适配”可以整个关掉；“显示追踪数据”里的 `build` 一行是当前量到的值。
- 想直接看模型怎么变：`…/xray/?shape=child#demo`、`?shape=slim`、`?shape=broad`，或用 `?youth=0.6&frame=-0.5&hip=0.8&build=0.3` 自己组合。
- 模型底本只有一副（BodyParts3D 是一位成年男性的数据）。在可商用的许可下没有找到女性或儿童的全身骨架数据，所以差别靠参数变形得到。
  以后拿到这样的数据，可以用 `tools/build_body.py` 的同一套分组和关节做成另一副底本。

## 地址参数

| 参数 | 作用 |
|---|---|
| `?screen=32` / `86` / `desk` / `auto` | 屏幕类型 |
| `?base=58` | 86 寸布局的界面中线高度，35–75（屏高的百分比，从底边量） |
| `?lang=zh` / `en` | 界面语言 |
| `?rotate=90` / `180` / `270` | 摄像头是横着或倒着装的时候，把画面转正 |
| `?cam=1080` / `2160` | 向摄像头要更清晰的画面（默认 1280×720）。大屏上画面更清楚，但更吃性能 |
| `?cam=native` | 不指定分辨率，用摄像头自己的格式（适合直接输出竖画面的摄像头） |
| `?autostart` | 不等点击，直接开始（没授权过摄像头时，浏览器仍会弹授权框） |
| `?local` | 运行库和模型从 `./vendor` 读取，不访问外网 |
| `#demo` | 演示场景：不开摄像头，一副站立的骨架，用来检查布局、显卡和体型变化（配合 `?shape=` 等） |

设置面板：点带滑块图标的圆形按钮（32 寸在右上角，86 寸在右侧图层按钮下方），或按 `S` 键；`F` 键切换全屏。面板里可以改屏幕类型、
界面中线高度、语言、摄像头、画面旋转、镜像、外观（X 光 / 实体）、亮度、透出真实画面的程度、镜片大小、身体轮廓、体型适配、
头部贴合微调、性能模式、身体追踪精度，以及“显示追踪数据”。

## 无人值守

- 摄像头权限已经授予时，页面打开后自动开始，不需要点“开始”。
- Chrome 的 kiosk 模式启动示例（`--use-fake-ui-for-media-stream` 让这个浏览器实例不再弹摄像头授权框，只应在专用的屏幕上用）：
  `chrome --kiosk --use-fake-ui-for-media-stream "https://<地址>/xray/?screen=86"`
- 摄像头断开或停止出画面时，每隔几秒重新打开，直到恢复。追踪器连续报错 8 秒会刷新页面（两分钟内最多一次）。
- 运行期间请求屏幕常亮。

## 离线

```bash
sh tools/fetch_vendor.sh        # 需要 npm 和 curl；把运行库和四个模型下载到 ./vendor（约 47 MB，不入库）
```

然后把整个 `xray/` 目录用任意静态服务器提供出来（例如 `python3 -m http.server`），打开 `http://localhost:8000/?local`。
字体在线时从 Google Fonts 加载，离线时退回系统字体。

## 它是怎么工作的

- **三个追踪器**（MediaPipe）：身体 33 个点、脸 478 个点加一个头部姿态矩阵、手 21 个点。身体追踪每帧都跑；脸部追踪在头够大时才跑
  （其余时间隔一阵试一次）；手部追踪只在身体追踪器看到一只够大的手时才跑。
- **骨架**来自 BodyParts3D 的 265 个骨骼部件，分成 17 组（头骨、颈椎、胸廓、腰椎、骨盆，左右各一的上臂、前臂、手、大腿、小腿、足），
  完整版 12 万个三角面，轻量版 3.8 万个。每组保持在模型原有的坐标里，由一个 4×4 矩阵（模型毫米 → 屏幕像素）摆到追踪到的关节上；
  腰椎在骨盆和胸廓两个矩阵之间逐顶点过渡，颈椎在胸廓和头之间过渡，所以弯腰、转头时脊柱是连续的。
  体型变化是在这之前、在模型自己的坐标里做的：绕一个点的缩放，沿一个方向渐变（头骨是从面部到脑颅，胸廓是从上到下，骨盆是从髋关节往上）。
- **深度**取自追踪器给出的三维骨架，再按画面里的人有多大换算成像素。那副三维骨架是按标准成人归一化的，所以体型只从画面里的二维位置量。
- **走近以后**，头部交给脸部追踪器：头骨、大脑、面部肌肉按脸的姿态画，张嘴时下颌会动，颈椎挂在这个头骨下面。
- **只画看得见的**。追踪器对画面外或被挡住的关节也会给出猜测，照着画会出现乱飞的骨头，所以：
  肘、腕、膝、踝的可信度要到 0.75 才显示（显示后降到 0.6 以下才收起，避免闪烁）；髋不在画面里时，躯干按直立处理；
  躯干偏离竖直超过 75° 的结果整个丢弃（多半是把别的东西认成了人）；带关节的手只在身体追踪器也看到手的位置出现。
- **跟不上摄像头时自动让步**：先降低手和身体追踪的频率，再降低 3D 图层的清晰度，再换成轻量版模型，有余量时再升回来。
  没有显卡加速时一直用轻量版，并在屏幕空闲时提示打开硬件加速。

## 重新生成数据

```bash
# 全身骨架：BodyParts3D 3.0 的 STL（例如 github.com/Kevin-Mattheus-Moerman/BodyParts3D 的 assets/BodyParts3D_data）
python3 tools/parts.py <BodyParts3D_data>                 # 列出每组用了哪些部件
python3 tools/build_body.py <BodyParts3D_data> data       # 需要 numpy、fast_simplification；写出完整版和轻量版

# 头部和手：用 ../xray-teardown/tools/extract.py 从原版页面取出的 meta.json / meshdata.bin
python3 tools/build_head.py <meta.json> <meshdata.bin> <canonical_face_model.obj> data/body.json data/body.bin data

python3 tools/bundle.py                                   # 单文件版 → dist/xray-mirror.html
```

## 测试

```bash
# <deps> 的准备方法见 ../xray-teardown/README.md，另外需要 models/pose_landmarker_lite.task 和 pose_landmarker_full.task
node tools/run.mjs demo <deps> out.png 1080 1920 "screen=86&lang=zh&shape=child"

node tools/run.mjs live <deps> out.png camera.y4m 1080 1920 "screen=32&cam=native" '{"brain":true,"debug":true}'
```

`run.mjs` 用无界面的 Chromium 打开页面，把一段视频当作摄像头，外部请求只由本地文件应答，其余一律拦截并列出。
只给测试用的地址参数：`?delegate=gpu`（没有显卡时也让追踪器走显卡路径，用来测身体轮廓）、`?sweep=0.5`（把扫描定格在一半）、
`?probe`（把追踪数据挂到 `window.__xr`）、`?still`（演示场景只画一帧）。

## 验证过什么

全部在一个没有显卡的 4 核沙箱里完成，摄像头用照片或由照片合成的视频代替。

- 全身竖画面（86 寸布局）、半身近景（32 寸布局，开大脑或面部肌肉）、横向摄像头裁成竖屏、横屏、摄像头旋转 270°、演示场景、中英文界面。
- 流程：空场 6 秒后出现待机卡片；人出现后扫描揭示、5 秒后出第一句提示、走近后提示张嘴；开始卡片上的屏幕选择。
- 一段由全身照片合成的“走近再走远”视频：远近切换、髋部出画和回到画面时骨架连续，没有乱飞的骨头。
- 体型：演示场景的四种体型（标准、儿童、瘦窄、宽厚）形状变化符合预期。在 20 张公开样例照片上用同一套公式量头身比（成人基准为 1）：
  站姿全身的成人 0.8–1.16（门槛 1.15），半身近景 1.04–1.31（近处头显得大，门槛 1.32），都不触发或几乎不触发儿童比例；
  一张蹲着的成人照片量到 1.29，被算成 0.28 的儿童比例（蹲着时身体显得小）。肩、髋比例随人而变。
- 身体轮廓（显卡路径由软件模拟，只验证功能不验证速度）：压暗区域贴合人的轮廓；运行中切换身体追踪模型、开关轮廓都能继续跟踪。
- 摄像头中途停止出画面：约 5 秒后自动重新打开并恢复跟踪。
- 单文件版在没有 `data/` 目录的情况下运行。
- 帧率（软件渲染，最差情况）：1080×1920 下实时约 2–5 帧/秒，540×960 下 8–10 帧/秒；演示场景约 10 帧/秒。
  这里慢的主要是软件合成整屏画面和在处理器上跑追踪器，轻量版模型只帮到一小部分。

## 没验证的

- **真实设备上的帧率。** 沙箱没有显卡，上面的数字只能当下限。
- **真实的小孩。** 能拿到的样例照片里没有清楚的幼儿全身照，儿童比例只在演示场景里和按公式推算过；大约 6 岁以下头身比才明显，
  再大的孩子比例接近成人，主要靠各段骨骼的长度去适配。
- **胖瘦的测量。** 只在 6 张照片上看过数值，瘦的人偏低、穿宽松衣服的人偏高，方向对但很粗。
- 真实摄像头下人在动的时候：延迟、抖动、不同光线。合成视频只有缩放，没有肢体动作。
- 真实的 32 寸和 86 寸屏：界面的实际大小和位置是按像素比例推算的，没有在实物上看过。
- 真显卡上的身体轮廓图层：功能在模拟的显卡路径上通过了，真机上如果画面异常，把设置里的“身体轮廓”关掉即可回到旧画法。
- 多人同时入镜、逆光、镜头装得很高时的俯视角度。

## 已知限制

- 一次只跟踪一个人。
- 只有骨骼有全身模型；肌肉只有面部的，和大脑一样只在走近以后显示。
- 没有原版的解剖标签，也没有“只显示半边”的剖切方式（保留了随手移动的圆形镜片）。
- 远景时下颌不动。
- 竖屏配横向输出的摄像头时，屏幕只显示画面中间约三分之一的宽度，要站得比较远才能全身入镜。
  摄像头能竖着装的话，竖装并用“画面旋转”转正，视野会大很多。
- 模型是一副通用骨架按身体比例调整得到的，表示各结构通常所在的位置，不是对本人的扫描，也不是医疗工具。
